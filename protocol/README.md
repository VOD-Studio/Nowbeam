# Nowbeam 上报协议 v1

本文是接收方接入的规范；`MUST` / `MUST NOT` / `SHOULD` 按 RFC 2119 理解。当前尚无已完成的产品实现。消息结构由 [JSON Schema](v1/message.schema.json) 定义，示例见 [examples.json](v1/examples.json)。Schema 只能校验单条消息，不能替代下文的连接归属、顺序、时间和授权规则。

## 1. 角色与前提

客户端是向某个目的地发送状态的软件；接收端是实现本协议的后端。接收端可以是网站自己的后端，不要求使用 Nowbeam 独立服务或任何指定语言。一个客户端可连接多个接收端，各自独立鉴权和维护状态。

每个上报凭证 MUST 由接收方预先绑定到一个设备身份，且只有该设备的上报权限。不能信任客户端提交一个任意设备 ID 来选择要改写的状态。凭证签发方式不属于通用线协议，可以由接收方现有管理界面实现。

本协议不提供远程控制、远程采集开关、播放器控制、命令执行、文件访问或活动历史。服务端消息只有 `welcome`、`ack`、`error`；客户端消息只有 `snapshot`。

## 2. 建立连接与身份

- 客户端连接用户显式配置的完整 `wss://` 地址；路由可由接收方决定。Nowbeam 独立服务的默认路由为 `/api/v1/ingest`。
- HTTP Upgrade 请求 MUST 包含 `Authorization: Bearer <接收方颁发的凭证>` 和 `Sec-WebSocket-Protocol: nowbeam.v1`。
- 接收方 MUST 在 Upgrade 成功前验证身份与权限，并且在成功响应中选中 `nowbeam.v1`。客户端不得把未选中该子协议的连接视为兼容。
- 无效凭证返回 HTTP 401，权限不足 403，未知路由 404，不支持 Nowbeam 子协议返回 400；不支持底层 WebSocket 版本按 RFC 6455 返回 426。
- 不把凭证放 URL、子协议字段、消息正文或日志；不使用 Cookie 作为本协议的身份。不自动跟随重定向或向另一个域名转发 Authorization。
- 使用系统证书验证，不绕过 TLS 失败。开发构建的明文 WS 例外仅限显式配置的回环地址，不属于公网部署方案。
- Origin 不代替身份认证。v1 是原生上报协议，浏览器直接上报不在首批范围；接收端默认拒绝不符合其明确策略的 Origin，不设置无条件跨域放行。

## 3. 消息与时间边界

一个完整 WebSocket 文本消息承载一个 UTF-8 JSON 对象，不使用换行分隔流，不接受二进制消息。完整消息（包括分片重组）最多 65,536 字节，必须在解析/分配大量内存前限制；不得以单个 frame 大小替代消息总大小。

JSON MUST 不包含重复键、NaN、Infinity、孤立代理码点或未声明字段；字符串按 Unicode 码点计算 Schema 长度，线上总大小按 UTF-8 字节计算。数字整数限于 JavaScript 安全整数范围。协议 v1 不协商消息压缩。

时间戳统一为 UTC：`YYYY-MM-DDTHH:mm:ssZ`，或带 1–3 位毫秒小数的同类格式。只接受实际日历日期，不使用闰秒的 `:60` 编码、时区偏移或控制字符。

| 参数 | v1 规定 |
| --- | --- |
| 变化发送 | 语义变化立即发送，可合并尚未发送的连续变化 |
| 无变化刷新 | 每 15,000 ms 发送重新确认有效性的完整快照 |
| 租约 | 每份新接受的快照，从接收端收到它的时间起 45,000 ms |
| 新连接第一份快照 | `welcome` 后 10,000 ms 内，否则关闭未取得写入权的连接 |
| ACK 等待 | 客户端至多等待 5,000 ms，超时断开并按恢复规则处理 |
| 完整消息大小 | 65,536 字节 |
| 关闭前撤回 | 有限时间尽力完成；客户端退出路径最多等待 1,000 ms，不能依赖退出通知必达 |

这些值是 v1 的一致性配置，不是尚未达成的性能实测。`welcome` 显式给出保活、租约和消息上限；客户端校验与 v1 相符后再发送。

WebSocket Ping/Pong 只检查传输连接。它们 MUST NOT 创建在线投影、更新活动字段或延长状态租约。接收端租约使用自己的单调时钟判定，UTC 时间只供响应与展示；客户端墙钟不具有续期权。

## 4. 消息类型

### `welcome`：接收端 → 客户端

握手成功后接收端首先发送。包含新的 `connectionId`、凭证绑定的 `deviceId`、`serverTime` 及规定的时间/大小参数。

- `connectionId` 每条连接新建，为随机 UUID v4，不能复用旧值。
- `deviceId` 是接收方签发的随机 UUID v4，仅在该接收端内稳定；不是硬件指纹、Mac 主机名、服务器内部主键或跨站标识。
- 发送 welcome 不意味着设备已经在线或新连接已接管写入。未启用分享的连接检查到此结束并主动断开，不上传活动。
- 未收到并校验 welcome 前，客户端 MUST NOT 发送快照。

### `snapshot`：客户端 → 接收端

携带 `protocolVersion: 1`、本连接的 `connectionId`、`sequence`、`observedAt` 和完整 `sources`。

`sequence` 从 1 开始，后续新快照按接受顺序加 1，范围为 1 至 9,007,199,254,740,991。达到上限前重新建立连接，不能回绕。每条连接的序号独立，不从客户端持久化活动历史恢复。

`sources` 总是包含下列三个键，键缺失不是清除，消息会被拒绝：

| 来源 | 非空结构 | 空值含义 |
| --- | --- | --- |
| `application` | `displayName` | 没有当前允许公开的应用 |
| `window` | `title` | 未开启、未授权、未命中白名单、没有窗口或读取失败 |
| `media` | 会话 ID、播放器展示名、曲名、可空艺人/专辑、播放信息 | 不存在仍有效且允许分享的媒体会话 |

新快照 MUST 原子替换全部来源。不能分别缓存应用和媒体后合并，也不能把缺失或 `null` 当作“沿用旧值”。三个来源都为 null 是有效的在线空快照。

`observedAt` 是客户端观测信息，不参与租约计算。客户端在创建快照时必须确认采集许可和来源有效性，不能在采集器已失效时持续复制旧状态保活。接收端不得因为客户端时间在未来就延后到期。

### `ack`：接收端 → 客户端

仅在合法快照完成原子接受后发送，包含相同 `connectionId`、已接受的 `sequence`、接收端 `receivedAt` 与 `expiresAt`。正常新接受的快照满足 `expiresAt = receivedAt + 45 秒`。

ACK 表示当前快照被接受，不表示写入了历史存储，也不保证任何第三方页面已经刷新。客户端只接受本连接对应序号的 ACK；旧连接回调不得改变当前目的地的成功状态。

### `error`：接收端 → 客户端

包含稳定英文 `code`、本连接 ID 和可空 `sequence`，随后关闭连接。错误码不含用户活动、令牌、SQL 或内部异常文本；面向用户的说明由客户端本地化。无法安全发送错误时可以直接关闭。

支持的码：`invalid_message`、`out_of_order`、`sequence_conflict`、`credential_revoked`、`session_replaced`、`internal_error`。不接受未知消息或字段后静默忽略。

## 5. 连接接管、顺序与重复

每个接收端维护每个设备的当前写入连接 ID、最后接受的序号/消息指纹、最近 ACK 和完整快照。以下步骤必须在同一设备状态操作内完成：

1. 新连接的第一份合法快照必须为序号 1。完整校验成功后，原子接管设备，隔离旧连接并替换旧快照；再发送 ACK。
2. 仅完成握手或发 welcome 的连接不能抢占已有健康连接，也不能清除其状态。
3. 旧连接失去写入权后，任何消息、超时、错误或关闭回调都不能更改新连接的状态；清理前必须比较连接 ID。
4. 当前连接的新快照必须是最后接受序号加 1。更小序号或跳号产生 `out_of_order`，不续期。
5. 与最后接受序号相同、语义内容完全一致的消息只返回原 ACK；**不得重新计算到期时间**。对象键顺序/无意义 JSON 空白不影响语义相等。
6. 相同序号但内容不同产生 `sequence_conflict`，不能覆盖内容或续期。接收方可只保存最后一条消息的规范化指纹，不保存历史消息。
7. 校验失败不能部分更新任何来源。当前写入连接被关闭时，按归属校验清除其活动和在线状态；未接管的候选连接失败不影响已有连接。

本协议不是靠 TCP 顺序就能省掉身份与序号检查：跨连接重连、并发关闭回调和延迟处理仍可能改变顺序。

## 6. 新鲜度、退出与恢复

- 接收方收到当前连接断开、主动撤销或有效关闭通知时，立即清除该连接的活动并取消其租约。
- 网络黑洞等无法检测断开的情况，到期调度器必须在租约到期后使状态失效；所有读取路径也必须过滤已经到期的数据。
- 到期之后同一连接不得靠迟到快照复活旧租约；先关闭它，再要求新握手、新 connectionId 和重新采集的快照。
- 锁屏或暂停整体分享发送全空快照。继续发送空快照可以表示在线，但不能公开“锁屏原因”等额外本机细节。
- 隐私规则收紧、来源关闭或权限撤销时，立即废弃尚未发出的旧投影。若旧快照正在等待 ACK，客户端可直接关闭旧连接并用新连接发送最新允许状态，不排队等待敏感旧内容继续发布。
- 禁用目的地、睡眠或退出时尽力发送清空后关闭；网络不可用时无法保证瞬时撤回，只能依赖接收方到期。界面与文档不得承诺删除已被第三方保存的副本。
- 每个目的地最多一条待确认消息和一份最新待发快照。普通连续变化覆盖尚未发送的旧值，不保存离线活动队列。
- 短暂网络错误使用有上限的退避重连（1 秒起、指数增长、上限 30 秒，并加随机抖动）；恢复后重新采集，序号从新连接的 1 开始，不重试旧连接的活动。
- 认证失败、协议不兼容、证书错误或当前连接被其他客户端取代时停止自动重连，提示用户处理，避免两台软件共用凭证无限抢占。
- 原生客户端创建新连接后，旧连接的晚到错误/关闭回调不能将新连接状态改成失败。
- 服务重启不恢复旧活动；所有旧连接 ID 失效。设备/凭证记录保留，活动等待新连接重新建立。

## 7. 媒体含义

- 首版只输出实际支持播放器当前有效的媒体会话，不根据前台应用、安装情况或进程名推断。
- `sessionId` 是客户端为当前媒体会话产生的随机 UUID v4，同一会话暂停/恢复保持稳定；换曲、会话结束后重新开始或采集进程重建时换新，不包含曲库 ID。
- `title` 与 `playerName` 必须是有意义的纯文本；无法可靠取得必要字段就清除媒体，不能伪造曲名。
- `artist` / `album` 缺失用 null；不通过账号、历史或缓存补齐。
- `playback.state` 仅为 `playing` 或 `paused`。已结束/停止的会话必须用 `media: null`，而不是定义一个永久停留的 stopped 对象。
- 暂停时 `rate` 必须为 0。播放时 `rate` 是可信的正数（不超过 4），不可靠时为 null；未知速率不能假装为 1 推进位置。
- `durationMs` 可靠时为正整数，否则 null。`positionMs` 为非负整数或 null，两者都有值时位置不能超过时长；这个跨字段约束必须由接收实现额外校验。
- 发送前使用本机单调时间将可靠位置更新到当前观测时刻；暂停或速率未知时不推进。接收方用 `receivedAt` 作为消费者的时间锚点，不用客户端墙钟计算新鲜度或无限推算进度。
- 这允许网络延迟产生的有限位置误差，不宣称采样和展示精确同步。消费者遇到未知位置/速率不绘制虚假进度，并在到期后停止展示。
- v1 不上传封面、图片字节、任意外链、播放器路径、账号或媒体历史。

## 8. 关闭码

| 情况 | Close code | 行为 |
| --- | --- | --- |
| 正常关闭 | 1000 | 当前连接拥有状态时清除 |
| 进程退出/端点离开 | 1001 | 清除，客户端按是否仍启用决定恢复 |
| 不支持的二进制消息 | 1003 | 拒绝，不产生状态副作用 |
| 无效 UTF-8 | 1007 | 拒绝 |
| JSON/Schema/顺序规则违规 | 1008 | 可先发稳定 error，关闭当前连接 |
| 完整消息过大 | 1009 | 限制发生在完整解析前 |
| 接收方内部错误 | 1011 | 不回显异常文本，隔离当前连接 |
| 已连接凭证被撤销 | 4001 | 立即清除，停止自动重连 |
| 被新连接取代 | 4002 | 旧连接失去写入权，不清除新状态 |
| 初始快照超时或租约到期 | 4003 | 关闭；恢复必须新握手 |

4000–4999 是 RFC 6455 允许的私用区间。不得在线路上发送保留码 1005、1006 或 1015。Close reason 只使用短错误码，不包含用户内容。

## 9. 接收方最小实现检查表

- 握手前校验设备凭证、选中正确子协议、限制文本消息大小。
- 按 Schema 校验并执行媒体位置等跨字段约束；拒绝重复 JSON 键及非有限数字。
- 实现 welcome → 第一份快照 → 原子接受 → ACK，不把“连接已打开”当“同步成功”。
- 一台设备只有一个当前写入连接，旧连接与旧清理回调被隔离。
- 全量替换、null 清除、重复 ACK 不续租、乱序不回灌。
- 有限状态租约、主动到期、读取时过期过滤、撤销与退出清理。
- 公开读取策略与上报鉴权分开，不因收到上报自动公开。
- 不保留活动历史，不记录敏感内容，消费者不能无限缓存旧状态。
- 语言、数据库、公开读取 URL 和网站推送机制由接收方自行选择。

## 10. 版本与验证

增加不兼容字段、消息类型或语义必须使用新的子协议版本，不能让 `nowbeam.v1` 在不同接收端拥有不同含义。未知字段默认拒绝是为了避免意外泄露本机原始字段；扩展以明确版本协商实现，不靠静默透传。

运行根目录 `make check` 验证消息 Schema、有效示例与拒绝边界。当前检查不建立 WebSocket、不实现接收端状态机，不能证明连接接管、租约定时器或真实播放器已经工作。产品完成前仍必须执行 [真实验收](../docs/product.md)。

规范依据：[RFC 6455](https://www.rfc-editor.org/rfc/rfc6455)、[JSON Schema 2020-12](https://json-schema.org/draft/2020-12)、[Apple WebSocket Task](https://developer.apple.com/documentation/foundation/urlsessionwebsockettask)。
